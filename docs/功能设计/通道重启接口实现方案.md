# 通道重启接口实现方案

## 1. 需求概述

实现一个**重启指定通道**的接口。`notifyFeServerReload` 只能重载配置，不能重启进程。需要通过杀死 fe_channel 进程的方式实现通道重启。

---

## 2. 进程与通道的关系

### 2.1 一对一映射

根据实际部署和代码分析，**1 个 fe_channel 进程 = 1 个通道**：

```
fe_channel_manage（父进程，PID 3139）
  ├── fe_channel 1 1  (PID 3140)  ← 通道组1 通道1
  ├── fe_channel 1 2  (PID 3204)  ← 通道组1 通道2
  ├── fe_channel 1 3  (PID 3263)  ← 通道组1 通道3
  └── ...
```

### 2.2 进程命名规则与 ID 关系

```
fe_channel <fedb_id> <server_id>
```

#### 各 ID 含义

| ID | C++ 字段 | 含义 | 获取方式 | 示例 |
|---|---|---|---|---|
| `fedb_id` | `c_server_id.m_ui2_node_no` | 节点编号，标识哪台机器 | 从 FE 配置文件中按 hostname 查找（`assign_to_host`） | 1 |
| `server_id` | `c_server_id.m_ui2_server_no` | 服务器进程编号，标识哪个 fe_channel 进程 | 通道的 `SERVER_GROUP_ID` | 1, 2, 3... |
| `channel_group_id` | `c_db_class_channel_group` 对象 ID | 通道组编号 | fe_config.xml 中 CHANNEL_GROUP 的 ID 属性 | 100, 200... |
| `SERVER_GROUP_ID` | `c_db_type_channel.m_ui2_server_group_id` | 通道所属的服务器编号（通道通过此字段关联到服务器进程） | fe_config.xml 中 CHANNEL 的 SERVER_GROUP_ID 属性 | 1, 2, 3... |

#### 各 ID 的关系

- `fedb_id`（节点 ID）：由 **hostname** 决定，从 FE 配置文件的 `m_node_id_and_names` 映射表中查找。与通道组、server_id **无直接关系**，是独立编号
- `server_id`（服务器进程 ID）：标识 fe_channel 进程，与通道组 ID **无关系**，独立编号
- `channel_group_id`（通道组 ID）：逻辑分组，与 fedb_id、server_id **均无关系**，独立编号
- `SERVER_GROUP_ID`：通道的属性，**关联到 server_id**，决定通道由哪个服务器进程管理

#### fedb_id 的获取原理

```cpp
// config_define.cpp:2494 — assign_to_host
bool c_fe_server_define::assign_to_host(const std::string & host_name) {
    std::string name = host_name.empty() ? c_system::get_host_name() : host_name;
    // 从 FE 配置文件中查找 hostname → node_id 的映射
    m_node_id_and_names.key2_to_key1(name, m_ui4_id);  // m_ui4_id 就是 fedb_id
}
```

FE 配置文件中维护了 `hostname → node_id` 的映射表（`m_node_id_and_names`），启动时通过 `c_system::get_host_name()` 获取当前机器 hostname，查表得到 fedb_id。

#### Go 侧是否需要传 fedb_id

**不需要。** Go 侧只需通过 `kill -9` 直接杀死 fe_channel 进程，看门狗会自动重启。进程定位通过 `ps` 命令匹配进程名中的 `server_id` 即可，无需知道 fedb_id。

#### 层级关系

```
节点（fedb_id = 1）
  ├── 服务器进程 1（server_id = 1）→ fe_channel 1 1
  │     ├── 通道组 A（channel_group_id = 100）
  │     │     └── 通道（SERVER_GROUP_ID = 1）
  │     └── 通道组 B（channel_group_id = 200）
  │           └── 通道（SERVER_GROUP_ID = 1）
  ├── 服务器进程 2（server_id = 2）→ fe_channel 1 2
  │     └── 通道组 C（channel_group_id = 300）
  │           └── 通道（SERVER_GROUP_ID = 2）
  └── ...
```

> 注：当前部署中每个服务器进程只管理一个通道（1 进程 = 1 通道），因此 `server_id == SERVER_GROUP_ID`，两者数值相等。

#### 通道与服务器的关联

通道的 `SERVER_GROUP_ID`（XML 中 `Channel.SERVER_GROUP_ID` 属性，Go 结构体 `Channel.ServerGroupID`）决定它由哪个服务器进程管理。

#### 重启时使用的 ID

重启通道时，需要通过通道的 `SERVER_GROUP_ID` 获取 **server_id**（服务器进程编号），用于在进程列表中定位 fe_channel 进程。由于当前部署中 1 进程 = 1 通道，`server_id == SERVER_GROUP_ID`，两者数值一致。

### 2.3 Singleton 保护

每个 fe_channel 进程启动时创建进程标记（fe_channel.cpp:1090）：

```cpp
c_system::create_mark("FE_CHANNEL", sid.get_server_id());
```

同一 server_id 只能有一个进程运行。

### 2.4 看门狗自动重启

c_fe_channel_manage 每 3 秒检查所有通道的 `m_ui4_watch_count`（fe_channel_manage.cpp:1634）。如果看门狗计数为 0 且超过 3 次，自动重启该进程：

```cpp
stop_server(server_id, true);   // kill -9 <pid>
start_server(server_id);         // 重新拉起 fe_channel 进程
```

### 2.5 关键结论

| 特性 | 说明 |
|------|------|
| 进程与通道 | 1:1 映射，每个通道独立进程 |
| 杀进程影响 | 只影响被杀的通道，不影响其他通道 |
| 重启机制 | 杀掉后由看门狗自动重启，或手动 stop + start |
| 进程标记 | `FE_CHANNEL` + server_id 唯一定位进程 |

## 3. 重启原理

### 3.1 通道重启原理

通过 `kill -9` 直接杀死 fe_channel 进程，fe_server 中的 c_fe_channel_manage 看门狗会自动重启该进程：

```
1. 查找 fe_channel 进程 PID
   → ps aux | grep "fe_channel <fedb_id> <server_id>" | awk '{print $2}'

2. kill -9 <pid>
   → 进程被杀，通道断开

3. c_fe_channel_manage 看门狗（每 3 秒检查一次）
   → 检测到 m_ui4_watch_count == 0
   → 连续 3 次后调用 stop_server + start_server
   → 重新拉起 fe_channel 进程，通道恢复
```

### 3.3 关键点

- fe_channel 进程被杀后，**不需要手动重启**，看门狗会自动拉起
- 从 kill 到进程恢复，约有 **3-10 秒**延迟（看门狗检测周期 × 3 次 + 进程启动时间）
- `kill -9` 是强制杀死，确保进程立即终止

## 4. 实现方案

### 4.1 新增 Handler

在 `../../handlers/feconfig.go` 中新增：

```go
import (
    "fmt"
    "net/http"
    "strconv"
    "strings"
    "webserver-arm/emsxmldb"
    "webserver-arm/log"
    "webserver-arm/models"

    "github.com/gin-gonic/gin"
)

// ChannelRestartItem 通道组维度的重启请求/结果
type ChannelRestartItem struct {
    ChannelGroupID int   `json:"channel_group_id"` // 通道组 ID
    ChannelIDs     []int `json:"channel_ids"`       // 该通道组下的通道 ID 列表
}

// RestartChannelsResponse 重启响应
type RestartChannelsResponse struct {
    Success []ChannelRestartItem `json:"success"`
    Fail    []ChannelRestartItem `json:"fail"`
}

// findFeChannelPID 通过 server_id 查找 fe_channel 进程的 PID
// 进程名格式: fe_channel <fedb_id> <server_id>
func findFeChannelPID(serverID string) (string, error) {
    // 使用 ps 查找匹配的 fe_channel 进程，提取 PID
    // 匹配模式: 命令行中包含 "fe_channel" 和 "<server_id>" 且 server_id 在末尾
    cmd := fmt.Sprintf("ps aux | grep 'fe_channel' | grep ' %s$' | grep -v grep | awk '{print $2}'", serverID)
    output, err := execCommandOutput(cmd)
    if err != nil {
        return "", fmt.Errorf("ps command failed: %w", err)
    }
    pid := strings.TrimSpace(output)
    if pid == "" {
        return "", fmt.Errorf("fe_channel process with server_id %s not found", serverID)
    }
    return pid, nil
}

// killProcess 强制杀死指定 PID 的进程
func killProcess(pid string) error {
    return execCommand(fmt.Sprintf("kill -9 %s", pid))
}

// RestartChannels 重启指定通道（通过杀死 fe_channel 进程，看门狗自动重启）
func RestartChannels(c *gin.Context) {
    var req []ChannelRestartItem
    if err := c.ShouldBindJSON(&req); err != nil {
        log.Errorf("RestartChannels: ShouldBindJSON failed: %v", err)
        c.JSON(http.StatusBadRequest, models.CommonResp{Code: http.StatusBadRequest, Message: err.Error()})
        return
    }

    if len(req) == 0 {
        c.JSON(http.StatusBadRequest, models.CommonResp{Code: http.StatusBadRequest, Message: "request body is required"})
        return
    }

    // 校验每个通道组的参数
    for i, item := range req {
        if item.ChannelGroupID < 0 {
            c.JSON(http.StatusBadRequest, models.CommonResp{Code: http.StatusBadRequest, Message: fmt.Sprintf("item[%d].channel_group_id must be >= 0", i)})
            return
        }
        if len(item.ChannelIDs) == 0 {
            c.JSON(http.StatusBadRequest, models.CommonResp{Code: http.StatusBadRequest, Message: fmt.Sprintf("item[%d].channel_ids is required and cannot be empty", i)})
            return
        }
        for j, chID := range item.ChannelIDs {
            if chID < 0 {
                c.JSON(http.StatusBadRequest, models.CommonResp{Code: http.StatusBadRequest, Message: fmt.Sprintf("item[%d].channel_ids[%d] must be >= 0, got %d", i, j, chID)})
                return
            }
        }
    }

    // 获取 feconfig，用于根据 channel_group_id + channel_id 查找 SERVER_GROUP_ID
    fecfg, err := emsxmldb.GetFeConfigXMLManager()
    if err != nil {
        log.Errorf("RestartChannels: GetFeConfigXMLManager failed: %v", err)
        c.JSON(http.StatusInternalServerError, models.CommonResp{Code: http.StatusInternalServerError, Message: err.Error()})
        return
    }

    // 按通道组维度收集成功和失败的通道
    resp := RestartChannelsResponse{
        Success: make([]ChannelRestartItem, 0),
        Fail:    make([]ChannelRestartItem, 0),
    }
    successMap := make(map[int][]int)
    failMap := make(map[int][]int)

    for _, item := range req {
        for _, chID := range item.ChannelIDs {
            // 通过 channel_group_id + channel_id 查找通道的 SERVER_GROUP_ID（即 server_id）
            ch, err := fecfg.GetChannelByID(item.ChannelGroupID, chID)
            if err != nil {
                log.Errorf("RestartChannels: GetChannelByID(%d, %d) failed: %v", item.ChannelGroupID, chID, err)
                failMap[item.ChannelGroupID] = append(failMap[item.ChannelGroupID], chID)
                continue
            }
            serverID := strconv.Itoa(ch.ServerGroupID)

            // 查找 fe_channel 进程 PID
            pid, err := findFeChannelPID(serverID)
            if err != nil {
                log.Errorf("RestartChannels: findFeChannelPID(%s) failed: %v", serverID, err)
                failMap[item.ChannelGroupID] = append(failMap[item.ChannelGroupID], chID)
                continue
            }

            // kill -9 强制杀死进程，c_fe_channel_manage 看门狗会自动重启
            log.Infof("RestartChannels killing fe_channel process: pid=%s, server_id=%s", pid, serverID)
            if err := killProcess(pid); err != nil {
                log.Errorf("RestartChannels kill process %s failed: %v", pid, err)
                failMap[item.ChannelGroupID] = append(failMap[item.ChannelGroupID], chID)
                continue
            }

            successMap[item.ChannelGroupID] = append(successMap[item.ChannelGroupID], chID)
            log.Infof("RestartChannels group %d channel %d killed (server %s, pid %s), watchdog will restart", item.ChannelGroupID, chID, serverID, pid)
        }
    }

    // 将 map 转换为数组
    for cgID, chIDs := range successMap {
        resp.Success = append(resp.Success, ChannelRestartItem{ChannelGroupID: cgID, ChannelIDs: chIDs})
    }
    for cgID, chIDs := range failMap {
        resp.Fail = append(resp.Fail, ChannelRestartItem{ChannelGroupID: cgID, ChannelIDs: chIDs})
    }

    c.JSON(http.StatusOK, gin.H{
        "code":    http.StatusOK,
        "message": "restart channels completed",
        "data":    resp,
    })
}
```

### 4.3 execCommand / execCommandOutput

`execCommand` 已存在于 `handlers/system.go:806`，可直接复用。新增 `execCommandOutput` 用于获取命令输出：

```go
func execCommand(cmd string) error {
    command := exec.Command("sh", "-c", cmd)
    output, err := command.CombinedOutput()
    if err != nil {
        return fmt.Errorf("error: %w, output: %s", err, string(output))
    }
    return nil
}

func execCommandOutput(cmd string) (string, error) {
    command := exec.Command("sh", "-c", cmd)
    output, err := command.CombinedOutput()
    if err != nil {
        return "", fmt.Errorf("error: %w, output: %s", err, string(output))
    }
    return string(output), nil
}
```

## 5. 接口定义

### 重启指定通道

**POST** `/api/v1/log/fecfg/channels/restart`

#### 请求体

```json
[
  {
    "channel_group_id": 1,
    "channel_ids": [1, 2]
  },
  {
    "channel_group_id": 2,
    "channel_ids": [3]
  }
]
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `channel_group_id` | int | ✅ | 通道组 ID |
| `channel_ids` | int[] | ✅ | 该通道组下要重启的通道 ID 列表 |

> 不同通道组下的通道 ID 可能重复，因此需要 channel_group_id + channel_id 唯一定位一个通道。

#### 响应（全部成功）

```json
{
  "code": 200,
  "message": "restart channels completed",
  "data": {
    "success": [
      {"channel_group_id": 1, "channels": [1, 2]},
      {"channel_group_id": 2, "channels": [3]}
    ],
    "fail": []
  }
}
```

#### 响应（部分失败）

```json
{
  "code": 200,
  "message": "restart channels completed",
  "data": {
    "success": [
      {"channel_group_id": 1, "channels": [1]}
    ],
    "fail": [
      {"channel_group_id": 1, "channels": [2]},
      {"channel_group_id": 2, "channels": [3]}
    ]
  }
}
```

#### 响应字段说明

请求和响应使用相同的数据结构 `ChannelRestartItem`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `data.success` | ChannelRestartItem[] | 重启成功的通道列表 |
| `data.success[].channel_group_id` | int | 通道组 ID |
| `data.success[].channel_ids` | int[] | 该通道组下重启成功的通道 ID 列表 |
| `data.fail` | ChannelRestartItem[] | 重启失败的通道列表 |
| `data.fail[].channel_group_id` | int | 通道组 ID |
| `data.fail[].channel_ids` | int[] | 该通道组下重启失败的通道 ID 列表 |

#### 错误码

| HTTP 状态码 | 说明 | 示例 |
|------------|------|------|
| 400 | 请求体格式错误或为空 | `"request body is required"` |
| 400 | channel_group_id 为负数 | `"item[0].channel_group_id must be >= 0"` |
| 400 | channel_ids 缺失或为空数组 | `"item[0].channel_ids is required and cannot be empty"` |
| 400 | channel_ids 中包含负数 | `"item[0].channel_ids[1] must be >= 0, got -1"` |
| 500 | feconfig 加载失败 | 内部错误信息 |

## 6. 与现有接口的关系

| 接口 | 路径 | 功能 | 机制 |
|------|------|------|------|
| 重载配置（现有） | `POST /fecfg/notifyreload` | 通知 FE 服务器重载配置文件 | `notifyFeServerReload`（MT_RELOAD 消息） |
| 重启通道（新增） | `POST /fecfg/channels/restart` | 杀死 fe_channel 进程，看门狗自动重启 | `kill -9 <pid>`（shell 命令） |

**区别**：
- `/notifyreload`：只重载配置，不重启进程，通道不断开
- `/channels/restart`：杀死进程并重启，通道会短暂断开后恢复

## 8. 调用链路

```
POST /api/v1/log/fecfg/channels/restart
  请求体: [{"channel_group_id": 1, "channel_ids": [1, 2]}, ...]
  → handlers.RestartChannels
    → 解析 JSON body，得到 []ChannelRestartItem
    → 获取 feconfig（用于查询 SERVER_GROUP_ID）
    → 遍历每个 ChannelRestartItem：
        → 遍历每个 channel_id：
            → fecfg.GetChannelByID(channel_group_id, channel_id)
              → 获取 Channel.ServerGroupID（即 server_id）
            → findFeChannelPID(server_id)
              → execCommandOutput("ps aux | grep 'fe_channel' | grep ' <server_id>$' | grep -v grep | awk '{print $2}'")
              → 返回 PID
            → killProcess(pid)
              → execCommand("kill -9 <pid>")
              → 进程被杀，通道断开
    → c_fe_channel_manage 看门狗（每 3 秒检查）
        → 检测到 m_ui4_watch_count == 0
        → 连续 3 次后调用 stop_server + start_server
        → 重新拉起 fe_channel 进程，通道恢复
    → 返回重启结果
```

## 9. 测试要点

1. **单通道重启**：传入单个通道组+通道 ID，验证进程被杀并由看门狗自动重启
2. **多通道重启**：传入多个通道组和通道，验证逐个重启
3. **跨通道组重复 ID**：两个通道组下都有 channel_id=1，验证通过 channel_group_id 正确区分
4. **无效 channel_group_id**：传入不存在的通道组 ID，验证返回 fail
5. **无效 channel_id**：传入通道组下不存在的通道 ID，验证返回 fail
6. **进程不存在**：通道对应的 fe_channel 进程未启动，验证返回 fail
7. **并发重启**：多个请求同时重启不同通道，验证无冲突
8. **通道恢复**：重启后通道状态从 CS_NOT_ACTIVED → CS_CONNECTED（约 3-10 秒）
9. **不影响其他通道**：重启通道 1 时，通道 2、3 的数据采集不受影响
10. **kill -9 验证**：重启前后通过 `ps aux | grep fe_channel` 确认 PID 变化

---

## 10. 注意事项

1. **重启期间通道断开**：从 kill 到进程重新启动并连接，约有 3-10 秒的断开时间
2. **数据丢失**：重启期间该通道采集的数据会丢失
3. **权限要求**：arm_web 进程需要有权限执行 `kill` 命令
