# 首页模块设计

> 状态: 设计阶段 | 负责人: slh

---

## 需求概述

为 EMS Web 首页提供数据展示支持：
1. 维护一个 JSON 配置文件（`homepage.json`），前端可分段修改，后端提供独立的修改接口和统一查询接口
2. 查询接口在原始配置基础上，补充 XML 中测点的 `name`、`unit` 字段返回给前端
3. 根据配置中的 OID 列表，查询实时数据（Cgo 调用 C 库）和历史数据（InfluxDB），返回给前端展示

> **OID 说明**：见项目 memory `project_oid_format.md`，OID 格式为 `rtuid-devid-tableNo-gin`，tableNo 固定绑定测点类型。

## 配置文件结构（homepage.json）

```json
{
  "topology": [
    {
      "no": 1,
      "show_name": "储能",
      "used": 1,
      "oid": "1-1-102-1",
      "type": 1,
      "show_unit": ""
    }
  ],
  "realtime": [
    {
      "no": 1,
      "show_name": "",
      "oid": "1-1-102-1",
      "type": 2,
      "table": { "0": "未发生", "1": "发生" }
    }
  ],
  "basic_info": [
    {
      "no": 1,
      "show_name": "电站名称",
      "type": 3,
      "show_value": "xxx电站",
      "unit": ""
    }
  ],
  "power_level": [
    {
      "no": 1,
      "show_name": "电网侧功率",
      "oid": "1-1-102-3",
      "type": 1,
      "show_unit": "kW"
    }
  ]
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `no` | int | 是 | 序号，唯一标识该条目在数组中的位置 |
| `show_name` | string | 否 | 展示名称，为空时前端可展示 XML name |
| `used` | int | 否 | 是否启用（仅 topology 有） |
| `oid` | string | type=1/2 时必填 | 绑定的测点 ID（格式 `rtuid-devid-tableNo-gin`） |
| `type` | int | 是 | 1=实时值，2=查表值，3=固定值（无需绑点） |
| `show_unit` | string | 否 | 展示单位，为空时可展示 XML unit |
| `table` | map | type=2 时必填 | 值→显示文本映射 |
| `show_value` | string | type=3 时必填 | 固定显示值 |

### 配置节说明

| 配置节 | 用途 | 说明 |
|---|---|---|
| `topology` | 拓扑图数据 | 前端拓扑图中各节点的实时值展示 |
| `realtime` | 实时告警数据 | 前端实时数据面板，通过 table 映射为文本 |
| `basic_info` | 基础信息 | 电站名称等固定展示信息 |
| `power_level` | 电力等级数据 | 电力等级相关的实时值展示，用于历史数据查询接口按维度返回 |

### 接口一：查询首页配置

```
GET /api/v1/log/homepage/config
```

**说明**：返回完整配置，在原始 JSON 基础上，为每个有 `oid` 的条目补充 XML 中测点的 `name` 和 `unit`。

**响应 200**：

```json
{
  "code": 200,
  "data": {
    "topology": [
      {
        "no": 1,
        "show_name": "储能",
        "used": 1,
        "oid": "1-1-102-1",
        "type": 1,
        "show_unit": "",
        "name": "储能PCS有功功率",
        "unit": "kW"
      }
    ],
    "realtime": [...],
    "basic_info": [...]
  }
}
```

**补充逻辑**（基于 type switch，不修改 Pointer 接口）：

```go
// enrichItems 为有 OID 的条目补充 name 和 unit
func enrichItems(items []ConfigItem) {
    for i := range items {
        if items[i].OID == "" {
            continue
        }
        point, ok := emsxmldb.GetPointByID(items[i].OID)
        if !ok {
            continue
        }
        items[i].Name = point.GetName()
        if p, ok := point.(*emsxmldb.Analog); ok {
            items[i].Unit = p.Unit
        }
    }
}
```

### 接口二：修改拓扑配置

```
POST /api/v1/log/homepage/config/topology
```

**请求体**：传入完整的 topology 数组（前端保存后整体提交）

```json
[
  { "no": 1, "show_name": "储能", "used": 1, "oid": "1-1-102-1", "type": 1, "show_unit": "" },
  { "no": 2, "show_name": "电网", "used": 1, "oid": "1-1-102-2", "type": 1, "show_unit": "" }
]
```

**处理逻辑**：

收到请求后，对 `items` 数组按以下规则处理 `no` 值，确保最终保存的配置中 `no` 不重复：

```
1. 遍历 items，记录已出现的 no 值
2. 若当前 item 的 no 不存在于已有 no 中 → 保留该 no
3. 若当前 item 的 no 与已有 no 重复 → 自动分配下一个可用 no
4. 最终 no 从 1 开始连续递增，无空洞
```

处理完后：
1. 更新内存中的 topology 配置
2. 持久化写回 `homepage.json`

**响应 200**：

```json
{ "code": 200, "message": "success" }
```

### 接口五：查询首页历史数据

```
POST /api/v1/log/influxdb/his/home
```

**说明**：自动从首页配置中读取 Topology 和 PowerLevel 的 OID，按类型分组后批量查询 InfluxDB 历史数据，一次性返回两个维度的历史数据。

**请求体**：

```json
{
  "start_time": "2026-01-01T00:00:00Z",
  "end_time": "2026-01-02T00:00:00Z",
  "interval": 300
}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `start_time` | string | 是 | 开始时间，RFC3339 格式 |
| `end_time` | string | 是 | 结束时间，RFC3339 格式，必须晚于 `start_time` |
| `interval` | int | 否 | 时间间隔（秒），默认 300 秒，最小 300 秒 |

**响应 200**：

```json
{
  "code": 200,
  "data": {
    "topology": [
      {
        "time": "2026-01-01T00:00:00Z",
        "data": { "1-1-102-1": 32.4, "1-1-102-2": 750.1 }
      }
    ],
    "power_level": [
      {
        "time": "2026-01-01T00:00:00Z",
        "data": { "1-1-102-3": 10.5 }
      }
    ]
  },
  "msg": "查询成功"
}
```

**处理逻辑**：

1. 读取 `HomepageConfig`，分别收集 `topology` 和 `power_level` 中绑定了 OID 的条目
2. 按 OID 第三段（tableNo）识别测点类型（101=digital, 102=analog, 105=pulse）
3. 对每种类型调用 `QueryHistoryData` 查询 InfluxDB
4. 按 Topology 和 PowerLevel 两个维度组装响应返回

> 单类型查询失败不阻塞其他类型，失败的类型结果中不含该类型数据。

## no 去重处理逻辑（伪代码）

```go
func deduplicateNo(items []ConfigItem) []ConfigItem {
    seen := make(map[int]bool)
    nextNo := 1

    for _, item := range items {
        if !seen[item.No] {
            // no 未出现过，保留
            seen[item.No] = true
        } else {
            // no 重复，自动分配新值
            for seen[nextNo] {
                nextNo++
            }
            item.No = nextNo
            seen[nextNo] = true
            nextNo++
        }
    }
    return items
}
```

## 实时数据查询方案（Cgo）

> 已确定使用 Cgo 接口（`cgolibparse`）直接通过 OID 查询实时数据，不走旧的 RPC 通道。

### 查询架构

```
DBMsgManager（cgolibparse 单例）
    │
    ├─ 启动时：DBCGOInit() 初始化 C 库
    │
    ├─ 后台协程 startGetPointsValue()：每 2 秒轮询
    │   ├─ 遍历已注册的 OID（uint64 编码）
    │   ├─ 按 tableNo 分组（遥测/遥信/...）
    │   └─ 调用 C.GetFieldsValues() 批量查询 → 缓存到 pointsValueMap
    │
    └─ 对外接口：RegisterPointsID(idNameMap, registerIDs)
        ├─ 返回 getValue()  → 从缓存读取 []PointValue
        └─ 返回 unRegister() → 取消订阅
```

### 首页模块接入流程

```go
// 1. 页面打开时：注册首页配置中的所有 OID
mgr, _ := cgolibparse.GetDBMsgManagerInstance()

oids := []string{"1-1-102-1", "1-1-102-2", ...}  // 从配置获取
idNameMap := map[string]string{
    "1-1-102-1": "储能PCS有功功率",  // 用于展示/日志
}
getValue, unRegister, _ := mgr.RegisterPointsID(idNameMap, oids)

// 2. 轮询或 WebSocket 推送时：获取当前值
values := getValue()
// []PointValue{
//   {OID: 123456, PointID: "1-1-102-1", Name: "储能PCS有功功率",
//    CurrentValue: "750.1", Quality: "0", SendTime: "2026-07-25T10:00:00"},
// }

// 3. 页面关闭时：取消订阅
unRegister()
```

### PointValue 结构

```go
type PointValue struct {
    OID          uint64 // uint64 编码的 OID
    PointID      string // 原始 OID 字符串，如 "1-1-102-1"
    Name         string // 显示名（RegisterPointsID 传入）
    CurrentValue string // 当前值（主显示值）
    RawValue     string // 原始值
    CtlValue     string // 遥调遥控预置值
    Dead         string // 死区值
    HisPeriod    string // 历史存盘周期
    Quality      string // 质量码
    SendTime     string // 发送时间
}
```

### OID → uint64 编码

```go
// "1-1-102-1" → uint64
rtuID(16bit) << 48 | deviceID(16bit) << 32 | tableNo(8bit) << 24 | gin(24bit)
```

## 实时数据推送方案（WebSocket 广播）

> 前端打开首页后，通过已有 WebSocket 连接（`/api/v1/log/ws/push`）发送订阅消息，后端收到后启动全局推送协程，广播给所有连接的用户。

### 架构

采用全局共享模式，不区分单个连接：

- `HomepageManager` 全局单例，维护引用计数和推送协程
- 第一个连接订阅 → 注册 OID + 启动推送协程
- 后续连接订阅 → 仅增加引用计数
- 最后一个连接取消订阅 → 停止协程 + 取消注册
- 推送协程每 2 秒执行一次：`getValue()` → `ClientMgr.PushMsg()` 广播到所有连接
- 每次收到 `homepage_subscribe` 时检查配置是否变化（OID 数组是否改变），若有变化则重新注册

### 订阅流程

```
前端打开首页
    ↓
WebSocket 连接已存在（/ws/push，登录时建立）
    ↓
前端发送：{"topic": "homepage_subscribe"}
    ↓
后端收到 → 读取配置 collectOids()
         → 对比 registeredOids 检测配置变化
         ├── 未变化 → subscribeCount++
         └── 有变化/首次 → 若已订阅则 stopPush()
                         → RegisterPointsID(newOids) → startPush()
                         → subscribeCount++
    ↓
推送协程每 2 秒：getValue() → 转换 → ClientMgr.PushMsg() 广播所有连接
    ↓
前端收到：{"topic": "homepage_data", "content": [...]}
```

### 取消订阅

```
前端离开首页
    ↓
前端发送：{"topic": "homepage_unsubscribe"}
    ↓
后端收到 → subscribeCount--
         → 若 subscribeCount == 0 → stopPush() + unRegister()
连接断开时 defer 自动调用 Unsubscribe()
```

### HomepageManager 结构（homepage/manager.go）

```go
type HomepageManager struct {
    subscribeCount int
    registeredOids []string          // 当前已注册的 OID 列表，用于对比配置变化
    getValue       func() []cgolibparse.PointValue
    unRegister     func()
    pushStop       context.CancelFunc
    mu             sync.Mutex
}

func (m *HomepageManager) Subscribe() {
    m.mu.Lock()
    defer m.mu.Unlock()

    cfg := GetConfigManager().GetConfig()
    newOids, newIdNameMap := collectOids(cfg)

    if m.subscribeCount > 0 && equalOids(m.registeredOids, newOids) {
        m.subscribeCount++
        return  // 配置未变，仅增加引用计数
    }

    // 配置有变化或首次订阅
    if m.subscribeCount > 0 {
        m.stopPush()
    }
    m.startPush(newOids, newIdNameMap)
    m.registeredOids = newOids
    m.subscribeCount++
}

func (m *HomepageManager) Unsubscribe() {
    m.mu.Lock()
    defer m.mu.Unlock()
    if m.subscribeCount <= 0 { return }
    m.subscribeCount--
    if m.subscribeCount == 0 {
        m.stopPush()
    }
}
```

### collectOids / equalOids

```go
func collectOids(cfg HomepageConfig) ([]string, map[string]string) {
    var oids []string
    idNameMap := make(map[string]string)
    addItems := func(items []ConfigItem) {
        for _, item := range items {
            if item.Type == 3 || item.OID == "" { continue }
            oids = append(oids, item.OID)
            name := item.ShowName
            if name == "" { name = item.Name }
            idNameMap[item.OID] = name
        }
    }
    addItems(cfg.Topology)
    addItems(cfg.Realtime)
    addItems(cfg.BasicInfo)
    return oids, idNameMap
}

func equalOids(a, b []string) bool {
    if len(a) != len(b) { return false }
    set := make(map[string]struct{}, len(a))
    for _, id := range a { set[id] = struct{}{} }
    for _, id := range b {
        if _, ok := set[id]; !ok { return false }
    }
    return true
}
```

### wshandler.go 改造

在 `ReadMessage` 循环中解析 JSON 消息，识别 topic 分发：

```go
for {
    _, p, err := conn.ReadMessage()
    if err != nil { return }

    var msg struct {
        Topic string `json:"topic"`
    }
    if err := json.Unmarshal(p, &msg); err != nil { continue }

    switch msg.Topic {
    case "homepage_subscribe":
        homepage.GetHomepageManager().Subscribe()
    case "homepage_unsubscribe":
        homepage.GetHomepageManager().Unsubscribe()
    }
}
```

连接断开时 defer 清理：

```go
defer func() {
    homepage.GetHomepageManager().Unsubscribe()
    // ... 原有清理逻辑
}()
```

### 推送数据格式

通过 `ClientMgr.PushMsg()` 广播到所有已连接用户，前端根据已缓存的配置自行匹配展示：

```json
{
  "topic": "homepage_data",
  "content": [
    { "oid": "1-1-102-1", "value": "750.1", "quality": "0", "sendtime": "2026-07-25T10:00:00", "dead": "0" },
    { "oid": "1-1-102-2", "value": "1", "quality": "0", "sendtime": "2026-07-25T10:00:00", "dead": "1" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `oid` | 测点 ID，用于前端匹配配置 |
| `value` | 当前值（CurrentValue），type=2 时为原始值，前端通过 table 映射 |
| `quality` | 质量码 |
| `sendtime` | 数据发送时间 |
| `dead` | 死数标识，直接透传 C 库返回值（string 类型） |

### type 值处理逻辑

| type | 处理 |
|---|---|
| 1 实时值 | 直接推送 `CurrentValue` |
| 2 查表值 | `CurrentValue` → `table` 映射为文本（前端处理） |
| 3 固定值 | 不注册 OID，不参与推送，前端直接使用 `show_value` |

## 数据流

```
GET /homepage/config
  → 读内存配置
  → findPointByOID() 层级遍历 → 补充 name、unit
  → 返回前端

POST /homepage/config/{section}
  → 解析请求体
  → no 去重处理
  → enrichItems() 补充 name/unit
  → 更新内存 → 写回 homepage.json

WebSocket: homepage_subscribe
  → collectOids() → 对比 registeredOids
  → 有变化：stopPush() → RegisterPointsID() → startPush()
  → 无变化：subscribeCount++
  → pushLoop：每 2 秒 getValue() → ClientMgr.PushMsg() 广播

WebSocket: homepage_unsubscribe / 连接断开
  → subscribeCount-- → 0 时 stopPush() + unRegister()
```
